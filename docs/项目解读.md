# 企业情报调研分析系统 · 项目解读

> 基于 LangGraph 的多 Agent 企业情报调研系统。给定一家公司，自动完成情报搜集 → 分析 → 风险评估 → 综合报告，全程支持人工审批（human-in-the-loop）与断点续跑，调研产出自动沉淀进可复用的 RAG 情报知识库。
>
> 本文分四部分：**一、总体架构**；**二、逐文件解读（含方法级说明）**；**三、执行一次任务的完整运行流程**；**四、关键设计机制速查**。

---

## 一、总体架构

```
                        ┌─────────────────────────────────────┐
                        │           Vue 3 SPA (web/)          │
                        │  时间线轮询 · 审批 · 报告 · 知识库检索  │
                        └──────────────┬──────────────────────┘
                                       │ REST (JSON)
                        ┌──────────────▼──────────────────────┐
                        │        FastAPI (api.py)             │
                        │  后台线程跑图 · 状态机 · 事件落库      │
                        └──────────────┬──────────────────────┘
                                       │
        ┌──────────────────────────────▼──────────────────────────────┐
        │                  LangGraph 主图 (engine/graph.py)            │
        │                                                             │
        │  START → intake ─┬─ standard ─→ collection_team             │
        │                  │                ├→ analysis_team ┐        │
        │                  │                └→ risk_team ─────┤        │
        │                  └─ deep ─→ deep_planner → researcher×N      │
        │                             ↑              │                 │
        │                             └── critic ◄───┘                 │
        │                                                             │
        │      → synthesizer → human_review(interrupt) → reporter     │
        └──────────────────────────────┬──────────────────────────────┘
                                       │
             ┌─────────────┬───────────┴──────────┬─────────────┐
             │  SQLite     │   Chroma (向量)       │  Tavily /   │
             │  任务/事件/   │   + FTS5 (BM25)      │  网页抓取    │
             │  报告/缓存   │   RRF 混合检索        │             │
             └─────────────┴──────────────────────┴─────────────┘
```

**双模式编排**

| 模式 | 拓扑 | 说明 |
|---|---|---|
| `standard`（分层团队） | 搜集组 → 分析组 ∥ 风控组（并行）→ 综合 | 固定 fan-out ×2，DAG 依赖：分析/风控消费搜集组产出 |
| `deep`（深度研究） | 规划器 → 并行研究员 ×N → Critic 反思循环 | 动态 fan-out，Critic 按覆盖缺口补充子问题，最多 `MAX_RESEARCH_ROUNDS` 轮 |

两种模式在 `synthesizer` 处汇合，之后走 `human_review(interrupt)` → `reporter` → END。

## 二、逐文件解读

### 2.1 入口层

#### `main.py` — CLI 入口（调试/CI 用）

| 方法 | 作用 |
|---|---|
| `main()` | 解析 `--company / --objective / --mode / --auto-approve`，构建图（带 checkpointer），生成 `task_id`/`thread_id` 并写入任务表，然后 `graph.stream(inputs, config)` 跑图；interrupt 后进入多轮审批循环（`input()` 读 y 或修改意见 → `Command(resume=decision)` 恢复），最后打印 `db.get_report()` |
| `_print_ev(ev)` | 格式化打印一条时间线事件（时间/节点/Agent/任务/详情） |
| `_cli_sink(task_id, ev)` | 注册到 `set_event_sink` 的实时事件汇：团队子图内部事件即时打印，不等子图跑完 |
| `_drain(stream)` | 消费图的事件流并打印；遇到 `__interrupt__` 返回 `True`（图暂停）；跳过 `TEAM_NODES`（已由 sink 打印，避免重复） |

#### `api.py` — FastAPI 后端（REST API + 静态托管 + 后台执行）

| 方法/对象 | 作用 |
|---|---|
| `lifespan(_app)` | 启动钩子：打印 embedding 配置状态；调用 `db.fail_stale_running_tasks()` 清理僵尸任务；注册实时事件汇 `set_event_sink(lambda tid, ev: db.save_event(tid, ev))` |
| `app` | FastAPI 实例；`/` 挂载 `web/` 静态目录托管 Vue 前端 |
| `_get_reader_graph()` | 惰性构建共享只读图（独立 checkpointer 连接），专用于 `get_state` / `delete_thread`，由 `_STATE_LOCK` 保护 |
| `_KB_POOL` | kb_search 专用常驻线程池（max_workers=2）。不用 `with` 上下文是因为其 `shutdown(wait=True)` 会阻塞到检索线程结束，使超时兜底失效 |
| `_now()` | 当前时间字符串 |
| `_config(thread_id)` | 组装 LangGraph 运行配置（thread_id + recursion_limit） |
| `_save_event(...)` | 事件落库（异常只告警不抛） |
| `_drain(task_id, thread_id, stream)` | 消费后台图事件流逐条落库（前端轮询即"实时"）；`__interrupt__` 时写入待审批事件；跳过 TEAM_NODES 防重复；返回是否 interrupt |
| `_run_background(...)` | **后台线程主体**：每次执行新建独立连接的 checkpointer（WAL，可多任务真并行）。三种入口：全新跑（inputs）、审批恢复（`Command(resume=decision)`）、断点重试（`graph.stream(None, ...)` 从最后成功节点继续）。结束后维护状态机 `running → awaiting_approval / completed / failed`，finally 关闭连接 |
| `create_task(body)` | `POST /api/tasks`：生成 task_id/thread_id 落库，起 daemon 线程执行 `_run_background` |
| `list_tasks / get_task / delete_task` | 任务 CRUD；`delete_task` 拒绝删除 running 任务（防脏数据竞态，409），删除前尽力清理 checkpointer 状态 |
| `get_events` | `GET /api/tasks/{id}/events`：时间线，前端 2s 轮询源 |
| `get_result` | 返回最终报告 + 情报明细（source_urls 反序列化为 list） |
| `get_approval` | interrupt 审批快照：`get_state` 判断 `"human_review" in snap.next` 是否等待中，返回草稿 + 全部 findings |
| `resume_task` | 仅 `awaiting_approval` 状态可 resume（否则 `Command(resume=...)` 会抛异常误标 failed）；置 running 后起线程恢复图 |
| `retry_task` | 仅 `failed` 状态可重试；`retry=True` 走 `graph.stream(None)` 从断点续跑 |
| `kb_search(q, k)` | 提交到 `_KB_POOL`，30s 超时返回 503（防外部 embedding API 卡死拖垮接口） |
| `TaskCreate / Decision` | Pydantic 请求模型（mode 正则限定 standard/deep） |

### 2.2 编排核心 `engine/`

#### `engine/state.py` — 全部共享状态与数据模型

| 成员 | 作用 |
|---|---|
| `add_list(left, right)` | 并行写入安全的列表合并 reducer（容忍 None）。**所有被并行节点写入的字段（findings/timeline）必须声明它，否则 Send fan-out 触发写冲突** |
| `now_str()` | 时间线事件时间戳（带完整日期，跨天排查不歧义） |
| `SubQuestion` | 深度模式子问题（id/question/priority 1-5） |
| `Finding` | **所有 Agent 的统一产出单元**：team（collection/analysis/risk/deep）、agent、task、content、source_urls、credibility（high/medium/low，按来源 URL 数量评级） |
| `Task / TaskList` | 团队子图内的执行任务（type + description） |
| `ReviewResult` | 组长质检结论（pass_ok + missing_tasks） |
| `PlanOutput` | 规划器结构化输出（sub_questions） |
| `QualityAssessment` | Critic 反思质检结论（overall_pass / coverage_gaps / contradictions / dimension_scores） |
| `MainState` | 主图 TypedDict：company/objective/mode/task_id/thread_id/auto_approve + plan + `findings: Annotated[list, add_list]` + research_round + critic_verdict + draft_report + human_feedback + final_report + timeline |
| `TeamState` | 团队子图状态：prior_findings（上游产出）、tasks、task（Send 注入）、findings/timeline（与主图同名同 reducer，自动映射）、quality_ok、revise_count |

#### `engine/config.py` — 全局配置与 LLM 双档路由

| 成员 | 作用 |
|---|---|
| `Settings` | pydantic-settings 配置类：LLM（`OPENAI_API_KEY` 兼容旧名 `DEEPSEEK_API_KEY`）、Tavily/Firecrawl、Embedding（默认硅基流动 bge-m3）、编排参数（max_research_rounds=3、max_team_revise=2、max_workers_tasks=4、max_worker_tool_calls=6、tool_output_max_chars=2500、recursion_limit=80）、data_dir。`env_file_encoding="utf-8-sig"` 容忍 BOM |
| `settings` | 模块级单例 |
| `get_llm(role)` | 按角色取 LLM（`_llm_cache` 缓存）：**strong**=规划/质检/综合，**cheap**=组长拆解/摘要；ChatOpenAI（temperature=0.2），任意 OpenAI 兼容服务可用 |

#### `engine/graph.py` — 主图组装（双模式）

| 方法 | 作用 |
|---|---|
| `build_graph(checkpointer=None)` | 组装 10 个节点 + 边：START→intake；intake 条件分流（mode）；standard 路径 `collection_team → _fan_out_analysis_risk → analysis_team ∥ risk_team → synthesizer`；deep 路径 `deep_planner → _fan_out_researchers → researcher → critic → critic_gate{pass/revise}`；汇合后 `synthesizer → human_review → human_gate{approve/revise} → reporter → END`；`compile(checkpointer=...)` |
| `_fan_out_analysis_risk(state)` | B 模式固定 fan-out：分析组与风控组各携一份 `prior_findings`（过滤 team=="collection"）并行执行；task_id 必须随 Send 下发（事件实时外推依赖它） |
| `_fan_out_researchers(state)` | C 模式动态 fan-out：按 `plan` 中子问题数量开 N 个并行 researcher |

#### `engine/prompts.py` — 全部提示词（str.format 占位符）

| 常量 | 作用 |
|---|---|
| `INTAKE_PROMPT` | 目标提炼（只输出提炼后语句） |
| `DEEP_PLANNER_PROMPT` / `GAP_PLANNER_PROMPT` | 全量拆解 3-6 个子问题 / 只针对覆盖缺口补充 1-4 个 |
| `CRITIC_PROMPT` | 反思质检：overall_pass / coverage_gaps / contradictions |
| `SYNTHESIZER_PROMPT` | 报告结构约定（摘要/概况/核心发现/SWOT/风险提示/结论），要求标注来源与可信度 |
| `WORKER_USER_PROMPT` / `RESEARCHER_PROMPT` | worker 用户消息（含执行纪律：轮数有限、连败即停、禁编造） |
| `WORKER_SYSTEM_PROMPTS` | 7 个 agent 角色人设 + 工具预算（search/registry/patent/finance/market/compliance/researcher） |
| `TEAM_LEAD_DECOMPOSE_PROMPTS` | 三个组长的任务拆解提示（各限定可用任务类型） |
| `TEAM_LEAD_REVIEW_PROMPT` | 组长质检（默认通过，仅实质性缺口才打回） |
| `JUDGE_PROMPT` | LLM-as-judge 五维评分 |

#### `engine/nodes/` — 主图原子节点

| 文件 | 方法 | 作用 |
|---|---|---|
| `intake.py` | `intake_node(state)` | 任务解析与模式分流入口。目标 ≤10 字才用 cheap LLM 精炼（实测精炼 8-24s，长目标性价比低）；空目标给默认值；写 timeline 事件 |
| `deep_planner.py` | `deep_planner_node(state)` | 首轮全量拆解；**有 critic_verdict.coverage_gaps 时只做 gap 补充规划**（避免全量重跑省 token）。structured_output 失败降级为单条兜底子问题；截取前 6 个；research_round+1 |
| `critic.py` | `critic_node(state)` | 反思质检：strong LLM structured_output 出 `QualityAssessment`；**质检异常时放行（overall_pass=True）防死循环** |
| | `critic_gate(state)` | 门控：通过 / 达轮次上限 / 无具体缺口 → pass，否则 revise 回 deep_planner |
| `synthesizer.py` | `synthesizer_node(state)` | 汇总 findings 起草报告：拼人工修改意见段（revise 回边时）+ 检索历史报告片段作结构参考（RAG 复用）+ 按 TEAM_ORDER 排序的 findings；起草失败降级 `_fallback_draft` 确定性简报（保证链路不中断） |
| | `_fallback_draft(...)` | 按团队分组罗列 findings 的降级稿 |
| `human_review.py` | `human_review_node(state)` | 人工审批节点：auto_approve 直接通过；否则收集 risk 组风险信号，调 `interrupt({draft, risk_flags})` **暂停图执行**，resume 值即 human_feedback |
| | `human_gate(state)` | feedback=="approve" → reporter，否则 → synthesizer 重新起草 |
| `reporter.py` | `reporter_node(state)` | 报告归档：① `db.save_report/save_findings` 结构化落库（失败显式告警不静默）；② `ingest_findings/ingest_report` 沉淀 RAG 知识库（双写幂等）；③ 置任务 completed |

#### `engine/teams/` — 团队子图

| 文件 | 方法 | 作用 |
|---|---|---|
| `common.py` | `WorkerSpec` | dataclass：节点名 / 可承接任务类型 / 工具 / system prompt |
| | `set_event_sink(cb)` / `_emit_live(tid, ev)` | 实时事件汇注册与外推：子图内部事件产生的瞬间回调（api 落库 / CLI 打印），否则整个子图（可达数分钟）期间前端无输出 |
| | `TEAM_NODES` | 三个团队节点名集合，消费端 `_drain` 据此跳过防重复 |
| | `_make_lead_decompose(team, allowed)` | 组长拆解节点工厂：**修订轮直接执行 missing 任务不再调 LLM**（防覆盖清单）；有上游情报时拼摘要段；cheap LLM structured_output 出 TaskList，过滤非法 type，失败降级单任务；截到 max_workers_tasks |
| | `_get_worker_agent(spec)` | 惰性构建 worker（模块级缓存），支持测试注入 FakeChatModel |
| | `_make_worker_node(spec, team)` | worker 节点工厂：调 `run_worker` 返回 (finding, event) |
| | `_make_assign(type_to_node)` | 组内 Send 并行：按任务 type 分发给对应 worker |
| | `_make_lead_review(team, allowed)` | 组长质检节点工厂：默认 ok=findings 数≥任务数，LLM structured_output 出 ReviewResult；missing 过滤到本组可承接类型；不通过且未达 max_team_revise 时置新 tasks 进组内修订轮，达上限放行 |
| | `_review_gate(state)` | quality_ok → END，否则回 lead_decompose |
| | `build_team(team, workers)` | 组装子图：`START → lead_decompose → (Send 并行 workers) → lead_review → {END / lead_decompose}` |
| | `wrap_team(subgraph)` | **把子图包装为主图节点：只回传 findings/timeline**（内部字段 tasks/quality_ok 不污染父图）；用 stream 而非 invoke 消费子图，每个内部节点完成的瞬间 `_emit_live` 外推事件 |
| `collection_team.py` | `build_collection_team()` / `collection_team_node` | 搜集组：search_agent（tavily_search+web_crawl+rag_retrieve）/ registry_agent / patent_agent，组内 Send 并行 |
| `analysis_team.py` | `build_analysis_team()` / `analysis_team_node` | 分析组：finance_agent / market_agent（消费搜集组 prior_findings，搜索仅补充） |
| `risk_team.py` | `build_risk_team()` / `risk_team_node` | 风控组：compliance_agent（诉讼/处罚/经营异常三类信号） |

#### `engine/agents/` — ReAct worker

| 文件 | 方法 | 作用 |
|---|---|---|
| `react_workers.py` | `compress_tool(tool, max_chars)` | 工具输出截断包装（搜索/抓取动辄上万字，全文回灌会让每轮 ReAct 上下文线性膨胀），保留原 name/description/args_schema |
| | `make_worker_agent(name, tools, system_prompt)` | `create_react_agent` 一行构建专职 worker（每个 agent 只绑 2-3 个相关工具，工具越多选错率越高）。注：该 API 在 LangGraph V1.0 弃用，requirements 已锁 `<2.0.0` |
| | `extract_urls(messages)` | 从完整消息轨迹（含工具参数与结果）正则抽 URL，去重取前 6 |
| | `_final_text(msgs)` | 取轨迹中最后一条有文本的 AI 消息（中途达限不丢产出） |
| | `run_worker(agent, ...)` | 执行单个 worker 返回 (Finding, 事件)。**用 `stream(values)` 收集轨迹而非 invoke**：触发 recursion_limit（`max_worker_tool_calls*2+2`）时 GraphRecursionError 前已收集消息仍可用（部分产出不丢弃）；credibility 按 URL 数评级（≥2 high / 有 medium / 无 low） |
| `researcher.py` | `_get_agent()` / `researcher_node(state)` | 深度模式研究员：模块级单例 agent（tavily_search+web_crawl+rag_retrieve），每个实例只答一个子问题（Send 入参 `{company, objective, sub_q}`），invoke 后组 Finding(team="deep") |

### 2.3 工具层 `tools/`

|---|---|---|
| `search.py` | `tavily_search(query, max_results)` | **三级降级链**：Tavily 主通道 → Firecrawl 降级（未配 key 跳过）→ 确定性 mock。结果写 SQLite 缓存（key=sha256(query\|n)）；**mock 永不写缓存**（防瞬时故障被固化）。通道来源写入结果首行（质检与可信度评级依赖） |

### 2.4 知识库 `knowledge/`

| 文件 | 方法 | 作用 |
|---|---|---|
| `vector_store.py` | `RemoteEmbeddingFunction` | OpenAI 兼容 `/embeddings` 接口的 Chroma EF（默认硅基流动 bge-m3，不依赖 Chroma 内置 ONNX——避免首次下载 80MB 且中文差）；未配 key 时 `__call__` 抛错由上层降级 |
| | `get_embedding_function() / _get_client() / get_collection(name)` | 惰性单例；PersistentClient 落 `data/chroma`；两个 collection：`intel_store`（情报）/ `reports_store`（历史报告），cosine 空间 |
| `ingest.py` | `_chunk_id(company, doc)` | chunk_id = md5(company\|content) —— **双写幂等的根基**，重跑不重复沉淀 |
| | `_vector_upsert(...)` | 向量写入；失败返回 False 不抛出（不连累 BM25） |
| | `ingest_findings(company, task_id, findings)` | 每条 Finding 一个 chunk 双写 intel_store（meta 含 company/team/agent/credibility/task_id/source_urls） |
| | `ingest_report(company, task_id, markdown)` | 报告按 `## ` 二级标题切分后双写 reports_store |
| `hybrid_retriever.py` | `rrf_fuse(rankings, k=60)` | Reciprocal Rank Fusion：每路按 `1/(k+rank+1)` 计分累加，两路都召回的 chunk 排前 |
| | `hybrid_retrieve(query, company, k, collection_name)` | 双路召回（Chroma 向量 20 条 + FTS5 BM25 20 条，向量失败自动只剩 BM25）→ RRF 融合 → 返回前 k 条 |
| | `rag_retrieve` | 包装为 LangChain `@tool` 供 worker 使用："优先于联网搜索使用" |

### 2.5 存储层 `storage/`

#### `storage/schema.sql` — 六张表 + 一个 FTS 虚拟表

| 表 | 用途 |
|---|---|
| `tasks` | 任务表（thread_id 唯一，关联 checkpointer 支持断点续跑；mode CHECK 约束） |
| `task_events` | Agent 执行时间线（前端时间线视图数据源，按 task_id 建索引） |
| `findings` | 调研发现明细（source_urls 存 JSON 字符串） |
| `reports` | 最终报告（task_id UNIQUE，INSERT OR REPLACE） |
| `search_cache` | Tavily 搜索缓存（避免重复消耗配额） |
| `eval_results` | LLM-as-judge 评估结果 |
| `chunks_fts` | FTS5 虚拟表，**trigram 分词器支持中文子串匹配**（unicode61 会把整句中文当单 token） |

#### `storage/db.py` — SQLite DAO + checkpointer 工厂

并发模型：FastAPI 后台线程 + API 请求线程共享进程级单连接，**全部读写经模块级 `RLock` 串行化**（防 "database is locked" 与交叉 commit）。

| 方法组 | 方法 | 作用 |
|---|---|---|
| 连接 | `get_conn()` | 惰性单连接（intel.db），首次连时执行 schema.sql 建表 |
| | `_write(sql, params)` | 串行化单语句写（execute + commit） |
| | `get_checkpointer()` | 共享单例 SqliteSaver（checkpoints.sqlite）——CLI/默认用；此前每次新建裸连接不关闭会泄漏句柄 |

| events | `save_event / list_events` | 时间线写入与查询 |
| findings | `save_findings / list_findings` | 明细批量写（单事务 commit）与查询 |
| reports | `save_report / get_report` | 报告持久化 |

## 三、执行一次任务的完整运行流程

### 3.1 Web 方式（主路径）

**阶段 0 — 启动**

1. `uvicorn api:app` → `lifespan()`：打印 embedding 状态 → `fail_stale_running_tasks()` 清僵尸 → `set_event_sink(db.save_event)` 注册实时事件汇 → 挂载 `web/` 静态目录。
2. 浏览器打开 `http://localhost:8000`，`index()` 返回 index.html，Vue 应用挂载，`refreshTasks()` 拉历史列表。

**阶段 1 — 发起任务**

3. 用户填公司/目标/模式 → `submitTask()` → `POST /api/tasks`。
4. `create_task()`：生成 task_id（12 位 hex）与 thread_id（32 位 hex）→ `db.create_task` 落库（status=running）→ 起 daemon 线程跑 `_run_background` → 返回 id。
5. 前端 `selectTask` 选中任务，`startPolling()` 每 2s 轮询 events 与任务状态。

**阶段 2 — 图执行（后台线程）**

6. `_run_background` 新建独立 WAL checkpointer → `build_graph` → `graph.stream(inputs, config)`。inputs 含 company/objective/mode/task_id/thread_id/auto_approve 及空集合字段。
7. **intake**：提炼目标（短目标才调 cheap LLM），timeline 记"任务解析"；条件边按 mode 分流。

**阶段 3a — standard 模式**

8. **collection_team**（wrap_team 包装的子图，以 stream 消费）：
   - `lead_decompose`：cheap LLM 拆 2-4 个搜集任务（search/registry/patent）；
   - `_assign` 按类型 Send 并行 → search_agent / registry_agent / patent_agent 各自 ReAct（工具输出先压缩、轮数受限、达限保留部分产出）产出 Finding；
   - `lead_review`：组长质检，实质缺口且未达修订上限 → 回 lead_decompose 补做 missing（最多 max_team_revise=2 轮），否则放行；
   - 每个内部节点完成的瞬间 `_emit_live` → sink → `db.save_event` → 前端 2s 后可见。
9. `_fan_out_analysis_risk`：**analysis_team ∥ risk_team 并行**（Send ×2），各携搜集组 findings 作 prior_findings，同样"拆解 → 并行 worker → 质检"子图循环。
10. 两团队经 add_list reducer 合并 findings/timeline 后汇合到 **synthesizer**。

**阶段 3b — deep 模式**

8'. **deep_planner**：strong LLM 拆 3-6 个子问题（round≥2 时只针对 coverage_gaps 补充）。
9'. `_fan_out_researchers`：按子问题数 **Send 动态 fan-out** N 个 researcher 并行取证。
10'. **critic**：strong LLM 四维反思质检；`critic_gate` 不通过且有缺口且未达 MAX_RESEARCH_ROUNDS → revise 回 deep_planner（循环）；否则 pass。

**阶段 4 — 审批（human-in-the-loop）**

11. **synthesizer**：检索历史报告片段作参考（RAG 复用）→ strong LLM 起草 Markdown（失败降级 `_fallback_draft`）→ 存 `draft_report`。
12. **human_review**：`interrupt({draft, risk_flags})` 暂停图，状态由 checkpointer 持久化（刷新/重启不丢）；后台线程检测到 `__interrupt__` → 置任务 `awaiting_approval`。
13. 前端轮询发现状态变化 → 展示 `ApprovalPanel`（`GET /approval` 经共享只读图 `get_state` 取快照）→ 用户点「通过」或填修改意见 → `POST /resume`。
14. `resume_task` 置 running → 新后台线程 `graph.stream(Command(resume=decision))` 恢复：approve → human_gate 走 reporter；修改意见 → 回 synthesizer 带意见重新起草 → 再次 interrupt → 循环直至通过。

**阶段 5 — 归档与沉淀**

15. **reporter**：`db.save_report/save_findings` 落库 → `ingest_findings + ingest_report` 双写知识库（FTS5 先行、向量 upsert 幂等）→ 置 completed → 图到 END。
16. 前端轮询检测 completed → 停止轮询 → 报告 tab 渲染（marked + DOMPurify），可下载 `.md`；情报进入知识库供后续 `GET /api/kb/search`（向量 + BM25 → RRF）检索复用。

**异常路径**：任一环节抛异常 → `_run_background` 记 error 事件并置 failed → 前端出现「从断点重试」→ `POST /retry` → `graph.stream(None)` 从检查点最后成功节点续跑（团队子图内部不落检查点，整体重跑，但此前节点不重复）。

### 3.2 CLI 方式（调试/CI）

`python main.py --company 小米 --mode standard --auto-approve`：与上面阶段 2-5 完全一致，区别仅在于：事件由 `_cli_sink` 即时打印而非落库；interrupt 后在终端 `input()` 交互审批；不依赖 FastAPI。`--auto-approve` 时 human_review 直接通过，适合评估与演示。

## 四、关键设计机制速查

| 机制 | 位置 | 要点 |
|---|---|---|
| 并行写安全 | `engine/state.py` | findings/timeline 声明 `Annotated[list, add_list]` reducer，Send fan-out 不写冲突 |
| 子图状态隔离 | `engine/teams/common.py::wrap_team` | 只回传 findings/timeline，tasks/quality_ok 等内部字段不污染父图 |
| 实时事件外推 | `common.py::set_event_sink/_emit_live` | 子图用 stream 消费，内部节点完成瞬间回调；api 落库 / CLI 打印 |
| 审批可恢复 | `nodes/human_review.py` + `storage/db.py` | interrupt 依赖 thread_id 稳定；checkpointer 独立 WAL 连接，服务重启仍可续跑 |
| 断点重试 | `api.py::_run_background(retry=True)` | `graph.stream(None)` 从最后成功节点继续；团队节点内部整体重跑 |
| 双写幂等 | `knowledge/ingest.py` | chunk_id = md5(company\|content)：向量 upsert 天然幂等，FTS 先删后插 |
| 混合检索降级 | `knowledge/hybrid_retriever.py` | 向量召回失败/未配 key 自动退化为纯 BM25，RRF 逻辑不变 |
| 搜索三级降级 | `tools/search.py` | Tavily → Firecrawl → 确定性 mock；mock 不写缓存防固化故障 |
| worker 防失控 | `engine/agents/react_workers.py` | 工具输出截断 2500 字 + ReAct 轮数上限，达限保留部分产出 |
| 质检防死循环 | `nodes/critic.py::critic_gate` | 质检异常放行；轮次上限强制放行；无具体缺口放行 |
| 起草防崩图 | `nodes/synthesizer.py::_fallback_draft` | LLM 起草失败降级为确定性简报，前序 agent 产出不丢失 |
| LLM 分档路由 | `engine/config.py::get_llm` | strong（规划/质检/综合）vs cheap（组长/摘要），成本可控 |
